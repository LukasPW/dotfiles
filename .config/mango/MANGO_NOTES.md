# Mango migration notes

Migration from Hyprland (Lua config) to Mango on:

- **Desktop:** NixOS (systemd, SDDM), hostname `Desktop-NixOS-BTW`, monitors `DP-1` + `DP-2`
- **Laptops:** one Gentoo (OpenRC, no greeter), one NixOS. Both use `eDP-1`

---

## File layout

```
~/.config/mango/
├── config.conf          # shared by all machines
├── autostart.sh         # shared by all machines (chmod +x)
├── colors.conf          # generated by matugen, sourced at the BOTTOM of config.conf
├── host.conf            # symlink, per machine, NOT in git
└── hosts/
    ├── Desktop-NixOS-BTW.conf   # monitorrules + viewcrossmon/tagcrossmon binds
    └── default.conf             # laptops + anything else: eDP-1 rule + plain view/tag binds

~/.config/swayidle/config        # per machine (monitor names differ)
```

## Packages

Only what's new for Mango. Existing tools (qs, dunst, nm-applet, easyeffects,
blueman, awww, gnome-keyring, rofi, kitty, thunar, librewolf, zen, brightnessctl,
playerctl, wireplumber) stay as they are.

| Purpose | Gentoo | NixOS |
|---|---|---|
| Compositor | `mango` (see below) | `programs.mango.enable = true;` |
| Idle / lock | `gui-apps/swayidle` | `pkgs.swayidle` |
| Polkit agent | `gnome-extra/polkit-gnome` | user service (see NixOS section) |
| Screenshots | `gui-apps/grim`, `gui-apps/slurp`, `gui-apps/wl-clipboard` | `pkgs.grim`, `pkgs.slurp`, `pkgs.wl-clipboard` |
| Portals | `gui-libs/xdg-desktop-portal-wlr`, `sys-apps/xdg-desktop-portal-gtk` | `xdg.portal.extraPortals = [ pkgs.xdg-desktop-portal-wlr pkgs.xdg-desktop-portal-gtk ];` |
| Monitor info | `gui-apps/wlr-randr` | `pkgs.wlr-randr` |
| Key names | `gui-apps/wev` | `pkgs.wev` |
| Script linting | `dev-util/shellcheck` (or `shellcheck-bin`) | `pkgs.shellcheck` |

### Getting Mango itself

- **Gentoo:** probably not in the main tree. Check `eix mango` for an overlay (e.g. GURU).
  Otherwise build from source: https://github.com/mangowm/mango/wiki/installation
- **NixOS:** `programs.mango` / `wayland.windowManager.mango` come from Mango's flake
  (`github:mangowm/mango`). Add it as a flake input and import its NixOS + Home Manager
  modules, unless your nixpkgs channel already packages it.
- Portals: check https://github.com/mangowm/mango/wiki/xdg-portals for a recommended
  portal config.

### Remove once Mango is confirmed working

Keep Hyprland as a fallback until then.

- `hyprpolkitagent`, `hypridle`, `hyprshot`, `hyprpicker`
- Eventually Hyprland itself, then `emerge --depclean -a` on Gentoo

## Per-machine setup (once per install)

```sh
cd ~/.config/mango

# desktop
ln -s hosts/Desktop-NixOS-BTW.conf host.conf

# laptops / anything else
ln -s hosts/default.conf host.conf

# screenshot folder (grim won't create it)
mkdir -p ~/Pictures/screenshots
```

- Create `~/.config/swayidle/config` with that machine's monitor names.
- Decide on lid behavior:
  - **Lock + suspend:** leave logind alone. swayidle `before-sleep` locks first.
  - **Lock only:** set `HandleLidSwitch=ignore` and use
    `switchbind=fold,spawn,qs ipc call lock lock`.
    - Gentoo: `/etc/elogind/logind.conf`
    - NixOS: `services.logind.settings.Login.HandleLidSwitch = "ignore";`
      (older releases: `services.logind.lidSwitch = "ignore";`)

### swayidle config example (desktop)

```
timeout 300 'qs ipc call lock lock'
timeout 600 'mmsg dispatch sleep_monitor,DP-1; mmsg dispatch sleep_monitor,DP-2' resume 'mmsg dispatch wakeup_monitor,DP-1; mmsg dispatch wakeup_monitor,DP-2'
before-sleep 'qs ipc call lock lock'
```

Laptops: same file with `eDP-1`.

## Gentoo specifics

Start Mango from the TTY. Put this in `~/.bash_profile` or `~/.zprofile`:

```sh
if [ -z "$WAYLAND_DISPLAY" ] && [ "$(tty)" = /dev/tty1 ]; then
  exec dbus-run-session mango
fi
```

- `echo $XDG_RUNTIME_DIR` on the TTY must print a path (elogind handles this).

## NixOS specifics

Polkit-gnome as a user service:

```nix
systemd.user.services.polkit-gnome-authentication-agent-1 = {
  description = "polkit-gnome authentication agent";
  wantedBy = [ "graphical-session.target" ];
  wants = [ "graphical-session.target" ];
  after = [ "graphical-session.target" ];
  serviceConfig = {
    Type = "simple";
    ExecStart = "${pkgs.polkit_gnome}/libexec/polkit-gnome-authentication-agent-1";
    Restart = "on-failure";
  };
};
```

- User services tied to `hyprland-session.target` must move to `graphical-session.target`.
- The HM mango module's `systemd.enable` (default on) provides `mango-session.target`.
- **Don't** set HM's `autostart_sh`. It would overwrite the shared `autostart.sh`.
- If HM complains `~/.config/mango/config.conf` already exists, the HM module is trying
  to generate it. Either manage the file yourself (no `settings`/`extraConfig`) or let
  HM own it. Don't mix the two.

## Config gotchas

- `viewcrossmon` / `tagcrossmon` take **tag first, then monitor**: `viewcrossmon,1,DP-1`
- `monitorrule` names are regexes, so anchor them: `name:^DP-1$`
- Modifier order doesn't matter: `SUPER+CTRL+ALT` = `alt+super+ctrl`.
  Check new binds against existing ones.
- `colors.conf` must stay at the **bottom** of `config.conf` (later lines win).
  Point matugen's Mango template output there.
- `circle_layout=...` is a setting, not a bind action. The bind is `switch_layout`.
- `exec-once` only runs at login. `autostart.sh` changes need a relog, not `SUPER+r`.
- Mango is fixed at 9 tags per monitor.

### Arrow-key layout

| Combo + arrow | Action |
|---|---|
| SUPER | focus (crosses monitors) |
| SUPER+SHIFT | swap window (crosses monitors) |
| SUPER+CTRL | view prev/next tag |
| SUPER+CTRL+ALT | move window to prev/next tag |
| SUPER+CTRL+SHIFT | move floating window |
| SUPER+ALT | move window to other monitor |
| SUPER+ALT+SHIFT | scroller stack |
| CTRL+ALT | resize window |

## Debugging

- Validate config before logging in: `mango -c ~/.config/mango/config.conf -p`
- Autostart: uncomment the two log lines at the top of `autostart.sh`, relog,
  read `~/.cache/mango-autostart.log`
- Polkit: `pkexec true` should show the GNOME password dialog
- Key does nothing: run `wev` and press it to see its real name
- Lint scripts: `shellcheck autostart.sh` (warning codes → https://www.shellcheck.net/wiki/)
